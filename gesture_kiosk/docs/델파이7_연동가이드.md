# 델파이7(Delphi 7) 연동 가이드 — 제스처 엔진 ↔ 회사 GUI 프로그램

> **2026-07-23 확정 — 파이프(stdio) 연동** (회사 요청: 엔진은 이벤트를 print만 한다).
> 델파이가 엔진을 자식 프로세스로 실행하고, 엔진이 표준 출력(stdout)에 찍는
> 텍스트 한 줄을 **익명 파이프**로 읽는다. 네트워크(UDP·웹소켓)는 전면 철회 —
> 포트·방화벽·유실 이슈가 소멸했다 (파이프는 같은 PC 안의 신뢰 채널이다).
> 엔진 쪽 구현: `src/pipeline/event_sender.py` (`StdioEventSender`).
> **델파이 쪽 참조 코드는 이 문서 §4가 전부다** — §4-1 유닛을 프로젝트에 추가하고
> §4-2를 메인 폼에 붙이면 수신부가 완성된다 (파이프 왕복 검증 완료 코드).

## 1. 통신 구조

```
델파이7 GUI 프로그램                          제스처 엔진 (python)
  CreateProcess로 엔진 실행  ─────────────►  py -3.11 main.py (시스템 파이썬)
  익명 파이프(stdout) 줄 단위 수신 ◄────────  이벤트 확정 시 print 한 줄
```

- 이벤트(엔진→GUI): stdout 텍스트 한 줄 — 이벤트 확정 순간 1건씩. 폴링 불필요.
- (선택) 제어(GUI→엔진): stdin 텍스트 한 줄 — `cam on`/`cam off`(카메라 창 토글),
  `quit`(종료). stdin 파이프를 연결한 경우에만 — 미연결이어도 엔진은 정상 구동.
- 같은 PC 안 파이프라 전달 순서 보장·유실 없음 (UDP 유실 협의 항목 소멸).
- 음성 안내(TTS)는 엔진에 없다 — 2026-07-22 제거, 회사 UI 담당.

## 2. 엔진 쪽 설정 (`configs/config.yaml`)

```yaml
event_output:
  mode: stdio             # 배포 기본값 — stdout에 이벤트 한 줄씩
```

로그는 stderr·파일(logs/)로만 나간다 — **stdout에는 이벤트 줄만 온다.**

## 3. 전송 규격

> ★2026-07-31: 엔진 **기본 출력이 간소 규격(name)** — 이벤트명 한 줄만
> (아래 10종 + CRLF). 아래 GESTURE|
> 규격(손·신뢰도·시각 포함)이 필요하면 config `event_output.format: text`로 전환.

### 3-1. 상세 규격 (format: text)

이벤트 1건 = ASCII 한 줄 (CRLF `#13#10` 종료):

```
GESTURE|이벤트명|손|신뢰도|시각\r\n
예) GESTURE|right|right|1.00|12345.678
    GESTURE|confirm|left|1.00|12346.912
```

| 필드 | 값 | 비고 |
|---|---|---|
| 1 | `GESTURE` 고정 | 규격 식별자 — 다른 줄은 무시하면 됨 |
| 2 | 이벤트명 (아래 표) | config classes와 동일 |
| 3 | `left` / `right` / 빈 문자열 | 궤적을 만든 손 (사용자 기준) |
| 4 | 신뢰도 (소수 2자리) | 현재 항상 1.00 |
| 5 | 엔진 단조시계 초 (소수 3자리) | 순서·중복 판별용 — 벽시계 아님 |

구분자 `|`는 값 안에 절대 등장하지 않는다 (필드 2·3은 영문 고정, 4·5는 숫자).

**이벤트 10종 (2026-07-29 개편 + 2026-07-31 손바닥·클릭 추가):**

| 이벤트명 | 사용자 동작 | UI가 할 일 |
|---|---|---|
| `left` / `right` / `select` | **한 손가락** + 좌/우/위 쓸기 | 포커스 1칸 이동 (+ 새 항목 낭독) |
| `back` | **주먹** + 왼쪽 | 이전 화면 |
| `home` | **주먹** + 위 | 처음 화면 |
| `confirm` | **주먹** + 오른쪽 | 현재 포커스 항목 실행 |
| `temp_left` / `temp_right` / `temp_top` | **손바닥(전부 폄)** + 좌/우/위 쓸기 | 회사 정의 예정(temp — 2026-07-31 추가) |
| `click` | **한 손가락** 제자리 더블 탭(검지 까딱 2회) | 클릭/실행 (회사 정의 예정) |

※ 구 `top`/`bottom`/`ok`는 더 이상 오지 않는다 — UI 분기문을 위 10종에
맞출 것 (아래 쓸기는 이벤트 없음).

## 4. 델파이7 수신 구현 — 완성 참조 코드

핵심 절차: ① `CreatePipe`로 익명 파이프 생성 → ② `CreateProcess`로 엔진 실행
(STARTUPINFO의 `hStdOutput`에 파이프 쓰기 끝을 연결) → ③ 수신 스레드가
`ReadFile`로 읽어 CRLF 단위로 자른다 → ④ `PostMessage`로 메인 폼에 전달.

### 4-1. EngineProcess.pas — 유닛 전체 (그대로 프로젝트에 추가, 수정 불필요)

```pascal
unit EngineProcess;

{ 제스처 엔진 실행 + 파이프(stdio) 수신 (2026-07-23 - 파이프 연동 확정).

  구조: CreatePipe(익명 파이프) -> CreateProcess(엔진 stdout을 파이프에 연결)
  -> 수신 스레드가 ReadFile로 읽어 CRLF 단위로 잘라 메인 폼에 PostMessage.
  UI는 절대 이 유닛(수신 스레드)에서 만지지 않는다 - 메시지로만 전달.

  호환: 델파이7과 최신 델파이(Community Edition 포함) 양쪽에서 컴파일되도록
  파이프 바이트 처리를 전부 AnsiChar/AnsiString으로 명시했다 - 델파이 2009+는
  Char/string이 2바이트(유니코드)라, 그대로 두면 ReadFile 바이트 수와 문자
  수가 어긋난다. 이벤트 줄은 ASCII라 Ansi로 충분하다. 문자열 전달도
  StrNew/StrDispose(버전별 소속 유닛이 다름) 대신 GetMem/FreeMem으로 통일 -
  수신 측은 FreeMem으로 해제한다.

  규칙:
  - 부모 쪽 파이프 "쓰기 끝"은 CreateProcess 직후 닫는다 - 안 닫으면 엔진이
    죽어도 EOF가 오지 않아 스레드가 영원히 기다린다.
  - 엔진 stderr(로그)는 NUL로 버린다 - 로그는 엔진의 logs/ 파일에 남는다.
    stdout은 이벤트 전용 채널(GESTURE| 줄)이다. }

interface

uses
  Windows, Messages, Classes, SysUtils;

const
  WM_GESTURE_EVENT = WM_USER + 101;   // LParam = PAnsiChar 한 줄 (수신 측이 FreeMem)
  WM_ENGINE_EXITED = WM_USER + 102;   // 엔진 종료(EOF) 알림 - 재기동 판단용

type
  TReadThread = class(TThread)
  private
    FPipe: THandle;
    FNotify: HWND;
  protected
    procedure Execute; override;
  public
    constructor Create(APipe: THandle; ANotify: HWND);
  end;

  TEngineProcess = class
  private
    FProcessInfo: TProcessInformation;
    FReadPipe: THandle;
    FRunning: Boolean;
  public
    function Start(const CommandLine, WorkDir: string; Notify: HWND): Boolean;
    procedure Stop;
    property IsRunning: Boolean read FRunning;
  end;

implementation

function NewAnsiLine(const S: AnsiString): PAnsiChar;
{ 수신 줄 1건의 복사 생성 - PostMessage로 스레드 경계를 넘기기 위함.
  받는 쪽(메인 폼)이 FreeMem으로 해제한다 (소유권 이전). }
begin
  GetMem(Result, Length(S) + 1);
  if Length(S) > 0 then
    Move(S[1], Result^, Length(S));
  Result[Length(S)] := #0;
end;

{ TReadThread }

constructor TReadThread.Create(APipe: THandle; ANotify: HWND);
begin
  FPipe := APipe;
  FNotify := ANotify;
  FreeOnTerminate := True;
  inherited Create(False);
end;

procedure TReadThread.Execute;
var
  Buf: array[0..1023] of AnsiChar;   // 바이트 버퍼 - 최신 델파이에서도 1바이트 유지
  Got: Cardinal;
  Acc, Line: AnsiString;
  P: Integer;
begin
  Acc := '';
  while ReadFile(FPipe, Buf, SizeOf(Buf), Got, nil) and (Got > 0) do
  begin
    SetString(Line, PAnsiChar(@Buf[0]), Integer(Got));
    Acc := Acc + Line;
    P := Pos(AnsiString(#13#10), Acc);
    while P > 0 do
    begin
      Line := Copy(Acc, 1, P - 1);
      Delete(Acc, 1, P + 1);
      if Line <> '' then
        PostMessage(FNotify, WM_GESTURE_EVENT, 0, LPARAM(NewAnsiLine(Line)));
      P := Pos(AnsiString(#13#10), Acc);
    end;
  end;
  PostMessage(FNotify, WM_ENGINE_EXITED, 0, 0);
end;

{ TEngineProcess }

function TEngineProcess.Start(const CommandLine, WorkDir: string; Notify: HWND): Boolean;
var
  SA: TSecurityAttributes;
  SI: TStartupInfo;
  WritePipe, NulHandle: THandle;
  Cmd: string;
begin
  Result := False;
  SA.nLength := SizeOf(SA);
  SA.bInheritHandle := True;
  SA.lpSecurityDescriptor := nil;
  if not CreatePipe(FReadPipe, WritePipe, @SA, 0) then Exit;
  // 읽기 끝은 자식에게 상속 금지 - 자식이 쥐면 엔진이 죽은 후에도 EOF가 안 온다
  SetHandleInformation(FReadPipe, HANDLE_FLAG_INHERIT, 0);

  NulHandle := CreateFile('NUL', GENERIC_WRITE, FILE_SHARE_WRITE, @SA,
                          OPEN_EXISTING, 0, 0);

  FillChar(SI, SizeOf(SI), 0);
  SI.cb := SizeOf(SI);
  SI.dwFlags := STARTF_USESTDHANDLES or STARTF_USESHOWWINDOW;
  SI.hStdInput := 0;
  SI.hStdOutput := WritePipe;      // 엔진 stdout -> 파이프 (이벤트 전용)
  SI.hStdError := NulHandle;       // 로그(stderr)는 버림 - 엔진 로그는 파일에 있다
  SI.wShowWindow := SW_HIDE;

  Cmd := CommandLine;              // CreateProcess는 쓰기 가능한 버퍼를 요구한다
  UniqueString(Cmd);
  Result := CreateProcess(nil, PChar(Cmd), nil, nil, True, CREATE_NO_WINDOW,
                          nil, PChar(WorkDir), SI, FProcessInfo);

  CloseHandle(WritePipe);          // 부모 쪽 쓰기 끝 닫기 (유닛 머리 주석 참고)
  if NulHandle <> INVALID_HANDLE_VALUE then CloseHandle(NulHandle);

  if not Result then
  begin
    CloseHandle(FReadPipe);
    Exit;
  end;
  FRunning := True;
  TReadThread.Create(FReadPipe, Notify);   // FreeOnTerminate - 스스로 해제
end;

procedure TEngineProcess.Stop;
begin
  if not FRunning then Exit;
  FRunning := False;
  TerminateProcess(FProcessInfo.hProcess, 0);
  CloseHandle(FProcessInfo.hProcess);
  CloseHandle(FProcessInfo.hThread);
  CloseHandle(FReadPipe);          // ReadFile 실패 -> 수신 스레드 종료
end;

end.
```

### 4-2. 메인 폼에 붙일 코드 (실행·수신·파싱·분기)

uses 절에 `EngineProcess`를 추가하고, 아래를 폼에 단다.
`TTimer`(예: `RestartTimer`, Interval 3000)를 폼에 하나 올려 재기동에 쓴다.

```pascal
const
  // 배포 PC에 맞게 이 두 줄만 조정 - exe가 엔진 폴더(gesture_kiosk\) 밖이면 경로 수정
  // 2026-08-03 확정: bat 경유 없이 py 직접 실행 + 가상환경 제거(사용자 결정)
  // - 시스템 파이썬에 직접 설치(install.bat)라 py 런처로 그대로 띄운다.
  // py.exe는 C:\Windows에 있어 PATH 이슈가 없다. 전체 경로를 쓰려면
  // 'C:\Windows\py.exe -3.11 main.py' 또는 파이썬 설치 경로의 python.exe
  ENGINE_COMMAND = 'py -3.11 main.py';
  ENGINE_WORKDIR = '..';            // exe 위치 기준 엔진 폴더 상대 경로

type
  TForm1 = class(TForm)
    // ... 기존 컨트롤 + RestartTimer: TTimer (Interval=3000)
  private
    FEngine: TEngineProcess;
    FEngineAlive: Boolean;
    procedure StartEngine;
    procedure HandleEvent(const EventName: string);
    procedure WMGestureEvent(var Msg: TMessage); message WM_GESTURE_EVENT;
    procedure WMEngineExited(var Msg: TMessage); message WM_ENGINE_EXITED;
  end;
```

```pascal
procedure TForm1.FormCreate(Sender: TObject);
begin
  FEngine := TEngineProcess.Create;
  StartEngine;
end;

procedure TForm1.FormClose(Sender: TObject; var Action: TCloseAction);
begin
  RestartTimer.Enabled := False;
  FEngine.Stop;                    // UI 종료 = 엔진도 종료 (§4-3 주의)
  FEngine.Free;
end;

procedure TForm1.StartEngine;
var
  WorkDir: string;
begin
  WorkDir := ExpandFileName(ExtractFilePath(Application.ExeName) + ENGINE_WORKDIR);
  FEngineAlive := FEngine.Start(ENGINE_COMMAND, WorkDir, Handle);
end;

procedure TForm1.RestartTimerTimer(Sender: TObject);
begin
  if not FEngineAlive then
  begin
    FEngine.Stop;
    StartEngine;                   // 엔진 사망·실행 실패 - 주기 재기동
  end;
end;

procedure TForm1.WMEngineExited(var Msg: TMessage);
begin
  FEngineAlive := False;           // 다음 RestartTimer 틱에 자동 재실행
end;

procedure TForm1.WMGestureEvent(var Msg: TMessage);
var
  Raw: PAnsiChar;
  Ansi: AnsiString;
  Line, Rest, EventName: string;
  Sep: Integer;
begin
  Raw := PAnsiChar(Msg.LParam);
  Ansi := Raw;
  FreeMem(Raw);                    // EngineProcess가 GetMem으로 넘긴 소유권 회수
  Line := string(Ansi);            // 델파이7=무변환 · 신형=ANSI->유니코드

  Rest := Line;
  Sep := Pos('|', Rest);
  if (Sep = 0) or (Copy(Rest, 1, Sep - 1) <> 'GESTURE') then Exit;  // 규격 외 줄 무시
  Delete(Rest, 1, Sep);
  Sep := Pos('|', Rest);
  if Sep = 0 then Exit;
  EventName := Copy(Rest, 1, Sep - 1);
  HandleEvent(EventName);
end;

procedure TForm1.HandleEvent(const EventName: string);
begin
  // 이벤트 7종 (§3) - 사용자 기준 방향 그대로 포커스를 옮긴다
  if EventName = 'left' then MoveFocus(-1, 0)
  else if EventName = 'right' then MoveFocus(1, 0)
  else if EventName = 'select' then MoveFocus(0, -1)   // 한 손가락+위 = 포커스 이동 (07-29)
  else if EventName = 'confirm' then ActivateFocused   // 구 ok (07-29 개명)
  else if EventName = 'back' then GoBack
  else if EventName = 'home' then GoHome;
  // MoveFocus/ActivateFocused/GoBack/GoHome은 실제 발급 화면의 컨트롤에 연결
end;
```

### 4-3. 주의사항

- **UI는 메인 스레드에서만** — 수신 스레드에서 컨트롤을 직접 만지지 말 것
  (PostMessage 필수 — §4-1이 이미 그렇게 돼 있다).
- 엔진 종료·비정상 종료 시 `ReadFile`이 0을 돌려 스레드가 끝나고
  `WM_ENGINE_EXITED`가 온다 — 위 RestartTimer 패턴으로 자동 재기동.
- UI 종료 시 `FEngine.Stop`(TerminateProcess)으로 엔진도 함께 종료할 것.
- 소스를 회사 프로젝트에 붙여넣은 뒤 저장할 때 **ANSI(CP949) 유지** — 델파이7은
  UTF-8 소스를 못 읽는다 (신형 델파이에서 저장 시 인코딩을 물으면 ANSI 선택).

## 5. 문제 해결 — 한글 깨짐 (델파이 작업 PC)

깨지는 **위치**에 따라 원인·처방이 다르다:

| 어디가 깨지나 | 원인 | 해결 |
|---|---|---|
| 델파이 IDE 편집기에서 소스 | ① IDE 에디터 폰트가 한글 미지원 (D7 기본 Courier New는 한글 글리프 없음) ② 시스템 코드페이지가 CP949가 아님 | ① Tools → Editor Options → Display → Editor font를 **굴림체/돋움체**로 변경 ② 아래 "시스템 로캘 절차" |
| 실행된 UI (버튼·제목) | 폰트 문자셋 | 폼 폰트를 굴림 + `HANGEUL_CHARSET`으로 지정 |
| 일반 편집기·GitHub에서 소스 | 고장 아님 — CP949를 UTF-8로 해석한 것 | 조치 불요 (델파이에선 정상). VS Code는 우하단 인코딩 → Reopen with Encoding → Korean(EUC-KR) |

**시스템 로캘 절차** (재부팅 필요 — 요즘 노트북에서 가장 흔한 범인):

```
설정 → 시간 및 언어 → 언어 및 지역 → 관리 언어 설정 → [시스템 로캘 변경]
→ "한국어(대한민국)" 선택
→ ☐ "Beta: 세계 언어 지원을 위해 Unicode UTF-8 사용" 체크 해제   ← 핵심
→ 재부팅
```

이 Beta 옵션이 켜져 있으면 델파이7 같은 ANSI 프로그램이 CP949 대신 UTF-8로
해석해서 소스·화면 한글이 전부 깨진다.

## 7. UI 정책 권장 + 협의 항목 (№7)

포커스·화면 처리는 UI 책임이다 — 아래를 권장한다:
