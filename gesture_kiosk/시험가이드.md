# 시험가이드 — 시험 장비(맥북)로 추론 시험

윈도우+NVIDIA 실기 확보 전에, **시험 장비로 파이프라인 전체를 실동작 검증**하기 위한
절차다. 배포 기준(윈도우·Python 3.11.5)과 다른 장비라 성능 수치는 참고용이고,
**동작 로직(제스처 판정·사용자 잠금·안내)** 검증이 목적이다. (2026-07-16 OCR 제거)

| 장비 | 브랜치 | 셋업 | 실행 | 접속 |
|---|---|---|---|---|
| 맥북 (Apple Silicon) | feat/test_think/mac | `bash setup_mac.sh` | `open scripts/run_demo_mac.command` | http://localhost:5001 |

---

## 1. 맥북 시험

```bash
git switch feat/test_think/mac
cd gesture_kiosk
bash setup_mac.sh                      # venv 재사용/생성 + 의존성 + smoke_test
open scripts/run_demo_mac.command      # ★ 반드시 이 방법 — 카메라 권한(TCC)이 Terminal에 귀속됨
```

> 제스처 엔진은 **RTMPose 포즈 단일 모델** — 쓸기(손목 궤적)·사용자 잠금이
> 키포인트 하나로 판정된다. 2026-07-16 토크백 정렬: 수직 쓸기 1회=확인/선택,
> 2연속=홈/이전(안전장치) — 1회 동작은 판정 창(1.2초)만큼 늦게 발화한다.
> 배포(feat/think_win_gpu) 구성과 동일하므로 여기서의 시험 결과가 배포 구성을 대변한다.

> 쓸기 임계는 **어깨너비 배수**(2026-07-16 정규화) — 카메라·사용자 거리가 달라져도
> 판정 기준이 자동 보정된다. 단, 팔 쓸기 궤적이 프레임 밖으로 나가면 인식 불가 —
> 카메라는 머리~골반과 양팔 쓸기 반경이 프레임에 들어오는 거리(0.8~1.5m 권장)로 배치.

맥 전용 주의 (docs/MAC_RUN_LOG.md):
- **IDE 하위 셸에서 run_demo.py 직접 실행 금지** — 카메라 권한 팝업이 안 떠서 실패한다
- 포트 5001 사용 (5000은 AirPlay 수신기가 선점) — config_mac.yaml에 반영돼 있음

## 2. 시험 시나리오 체크리스트 (기획서 6.2 연계)

각 항목 5회 시도, 성공 횟수 기록. 목표: 이벤트 단위 85% 이상.

| # | 시나리오 | 기대 이벤트 | 성공 |
|---|---|---|---|
| T1 | 팔을 오른쪽으로 쓸기 ×5 | move_right, 포커스 오른쪽 | /5 |
| T2 | 팔을 왼쪽으로 쓸기 ×5 | move_left, 포커스 왼쪽 | /5 |
| T3 | 줄 끝에서 move_right | 다음 줄 첫 칸으로 랩 (UI) | /5 |
| T4 | 아래로 쓸기 1회 | select (판정 창 1.2초 후), 선택 진입 | /5 |
| T4-1 | 위로 쓸기 1회 | read_focus — 현재 항목 다시 읽기 | /5 |
| T5 | 아래로 2연속 쓸기 | go_back, 이전 화면 | /5 |
| T6 | 위로 2연속 쓸기 | go_home, 처음 화면 | /5 |
| T6-2 | 팔을 대각선으로 흔들기 | 이벤트 없음 (주축 불명 보류) | /5 |
| T6-4 | 소매로 손을 완전히 가리고 좌/우 쓸기* | move 이벤트 (팔꿈치 폴백 — 추적점 "(E)" 표시) | /5 |
| T6-5 | 우로 쓸고 잠깐 있다가 팔 원위치 복귀 | 이벤트 없음 (복귀 스트로크 무시 — 정지 재장전) | /5 |
| T7 | 2명 프레임 진입, 뒷사람 손짓 | 잠긴 사용자만 반응 (배지 "사용자 고정됨") | /5 |
| T8 | 잠긴 사용자 이탈 2초 후 새 사용자 | 잠금 해제→재잠금 | /5 |

\* T6-4는 손 절단 사용자 모사 — 손목 키포인트 신뢰도가 떨어지면 추적점이 팔꿈치로
  바뀌고 CAM 화면 라벨에 "(E)"가 붙는다. 안 바뀌면(모델이 소매 끝을 손목으로 추정)
  kpt_conf_threshold를 올려 재시험.
